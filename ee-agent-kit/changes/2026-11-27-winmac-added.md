### Added
- Native Windows and macOS, not yet run on either: the first GitHub run of the desktop legs proves or refutes them. `install-macos.sh` installs Via on macOS (Apple Silicon; Intel best effort) for your own user: Homebrew's Python 3.12 and ngspice, KiCad 10.0.8 from its pinned DMG checked by SHA256, Temurin 21, the FreeRouting jar, a venv and a `workcenter` command; `--dry-run` prints every step and runs none. `install.ps1` installs Via natively on Windows for 1 user, with no administrator of its own; `workcenter.cmd` runs Via there. `toolchain/desktop.json` pins every download of both by its SHA256.
- `INSTALL.md`: Via's install on Ubuntu 24.04, macOS, Windows (native and WSL2) and Docker, a check per step and when it is done; the README's Install section gives a prompt you can paste to your coding agent, and says which computers GitHub's runners have proven (Ubuntu 24.04 only, so far).
- `tools/hostos.py` holds every difference between Linux, macOS and Windows that the tools need (root and lock folders, the venv's and KiCad's Python, kicad-cli and ngspice, KiCad's library folders, the AWT library and the JVM, ending a process tree, stop signals, the file lock, LF writes); on Linux each returns today's value.
- `workcenter doctor` has advisory `kicad-python` and `pcbnew` rows: KiCad's Python is asked, as a child, to import pcbnew; without it the row says why (`design --route` then leaves out stitching and pours).
- `workcenter new <dir> --empty` makes the folder alone, and `--deck <template> [--as <name>]` copies a template deck and its bounds into `sim/`; `new` writes the project's `.gitattributes` (`* -text`).
- `verify/desktop.csv`: every test file with where it runs (Linux, macOS and Windows; POSIX; Linux); a file is skipped at collection where its row leaves the system out, with the reason, and `testshards.py run --only verify/desktop.csv` runs the files that must pass on macOS and Windows.
- CI proves Windows and macOS: a `desktop` job on macos-latest and windows-latest installs with install-macos.sh or install.ps1 and runs `tools/ci/desktop_smoke.py`, on pull requests that touch install or platform code, every push to main and every night; an experimental WSL leg reports the WSL route's state in its own summary.
