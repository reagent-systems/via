### Changed
- The engine lock (`tools/enginelock.py`) imports and runs on Windows (msvcrt.locking, %LOCALAPPDATA%\Via\lock, SIGTERM and SIGBREAK) and on macOS without /proc: `enginelock.py hold` hands its ticket's descriptor to its command, so a run that dies keeps the lock until that command ends. Linux is unchanged. On Windows a run that dies frees the lock at once, even while an engine it started runs.
- The root, the venv's Python, kicad-cli, ngspice and KiCad's library folders come from `tools/hostos.py`; on Linux each is as before. Off Linux kicad-cli and ngspice are found on PATH, then in the install, and doctor names the program found and where it looked; the xvfb row is n/a. The Makefile and doctor's requirements fix command quote a path that holds a space (macOS's Application Support).
- The Java check for FreeRouting 1.9.0 holds each JDK to its own system's AWT library, follows macOS's /usr/bin/java to JAVA_HOME or /usr/libexec/java_home, and off Linux refuses a launcher with no JDK behind it and says to set JAVA; Linux's check and words are unchanged.
- The router's and `workcenter bench`'s time limit, and `workcenter mcp`'s stop, go through tools/hostos.py: on Windows a group of its own, Ctrl+Break, then `taskkill /T /F`; on Windows `workcenter mcp` reads stdin on another thread, so Ctrl+C and Ctrl+Break stop it while a host keeps stdin open, and says in 1 line that it sets no guard.
- `design` stitches a routed board's pours in a child process under KiCad's own Python (`tools/kicadchild.py`), so it works where Via's venv cannot import pcbnew (macOS, Windows); on Linux the files it writes are the same bytes as before. `workcenter next` names KiCad's installer when a board has a pour and KiCad's Python is not found.
- A Windows checkout holds the same bytes as a Linux one (`.gitattributes`: `* -text`), and every file a design writes is UTF-8 with LF line ends on every system; `design --check` names a difference in line ends alone as `line ends`, with the fix.
- `workcenter next` prints no `mkdir -p`, `cp` or `&&`: a missing folder is made by `workcenter new <dir> --empty`, a template deck is copied by `workcenter new <dir> --deck <template>`; the install line is each system's own.
- Engine output is read as UTF-8 on every system; a deck's sibling files are linked by a hard link or copied where a symlink is refused (Windows without Developer Mode), and made again on each run; a run deck names its models with forward slashes.
- Stand-in engines in the gate tests are Python programs (`conftest.stand_in`), not shell scripts; the test runner ends its shards through `tools/hostos.py` and loads where Python has no SIGHUP.
- nightly.yml's token reads the repository; only its `verify` job writes, to the ci-failure issue. The `verdict` line of ci.yml names whether the desktop legs were asked and their result.
