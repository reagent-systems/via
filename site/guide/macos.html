Installing Via on a Mac

One script installs everything Via needs on a Mac, for your own user. Here's what you need first, what it puts where, and how to check that it worked.

Letting your agent do it

You can hand the whole install to your coding agent: Claude Code, Codex, Cursor, Copilot, Gemini CLI or any other. Paste this to it, and it follows INSTALL.md one step at a time. It asks you before anything that needs sudo, an administrator, a restart or a big download.

Set up Via on this computer for me.
Read https://raw.githubusercontent.com/reagent-systems/via/main/INSTALL.md and follow it step by step.
If you cannot fetch it, clone https://github.com/reagent-systems/via and read INSTALL.md there.
Ask me before any command that needs sudo, an administrator, a restart, or a large download.
Stop when its "Done when" holds, and show me the last lines of each check.
If a step fails twice, stop and tell me what it printed.

If you'd rather do it yourself, these are the same steps.

1 What you need first

A Mac with Apple Silicon and macOS 12 or later. You'll also need Homebrew, which brings Python 3.12 and ngspice. If brew --version prints a version, you have it. If not, brew.sh gives the one command that installs it.

$ brew --version

Homebrew supports macOS 15 and later. On macOS 12 to 14 it builds Python and ngspice from source, which is slow and may fail.

2 Getting Via

Via installs from its own folder, so the first step is a copy of the repository in your home folder.

$ git clone https://github.com/reagent-systems/via ~/via

If macOS offers to install the command line developer tools, say yes and run the command again.

3 Looking before it installs

The dry run prints every step and every command, and installs, writes and downloads nothing. Its last line is [via] dry run: nothing was installed, written or downloaded.

$ cd ~/via && ./install-macos.sh --dry-run

4 Installing

This is the one command that installs everything, for your own user.

$ cd ~/via && ./install-macos.sh
  • KiCad 10.0.8 comes from its own disk image, about 1.4 GB, into /Applications/KiCad.
  • Java 21 and FreeRouting 1.9.0, the autorouter, go into ~/Library/Application Support/via, with Via's own Python environment.
  • Python 3.12 and ngspice come from Homebrew, into Homebrew's own folder.
  • The workcenter command goes into ~/.local/bin, and the script adds that folder to your PATH in ~/.zprofile (or ~/.bash_profile).

KiCad's disk image, Java and FreeRouting are checked against the SHA256 Via pins for each. Nothing runs as root unless /Applications isn't writable for you, and then the script asks before it uses sudo. Each step skips what's already done, so you can run it again.

If /Applications/KiCad already holds another KiCad, the script stops and keeps it. KiCad 10 can go beside it, in your own Applications folder, with no sudo at all.

$ cd ~/via && KICAD_DIR="$HOME/Applications/KiCad" ./install-macos.sh

5 Checking that it worked

Your open window still has the PATH it started with, so open a new Terminal window. It finds workcenter by name. Then run these three checks in Via's folder.

$ cd ~/via
$ workcenter doctor
$ workcenter gates tests/boards/pass-first-design
$ workcenter gates tests/boards/fail-drc-clearance
  • workcenter doctor lists each tool. Its first line is workcenter ee: ok, or degraded when the only tools it misses are openems, rsvg-convert and ffmpeg. The installer doesn't install those, and the install is done without them.
  • The first board is a pass, and the last line starts with GREEN.
  • The second board breaks a clearance on purpose, so its last line starts with RED. That's how you know the checks can fail. If it says GREEN, something's wrong with the install.

6 When a step fails

The script stops at its first problem with a line that starts with [via] ERROR: and says what went wrong. You can run the same step once more, since each step skips what's already done. If workcenter isn't found, the window is older than the install: open a new one, or run ~/.local/bin/workcenter doctor by its full path.

A few of Via's tools stay on Linux: openEMS (workcenter fields), the chip flow, and the tools that need KiCad's pcbnew in Via's own Python, like workcenter placement. They say SKIPPED on a Mac. Docker runs them.

Where this stands

We run this install on GitHub's Apple Silicon Macs. In run 46089464718 on 2026-11-28, the script installed Via and 878 of its 960 tests passed, with none failing. An Intel Mac is best effort: no test machine of ours is one, and it needs Homebrew already installed, since Homebrew's installer refuses an Intel Mac.

If a step still fails after a second try, we'd like to see what it printed. You can ask us in our Discord, or open an issue at GitHub with the command and its last 20 lines. Once Via's installed, the guide picks up from your first run of the checks. On a Windows PC, the Windows page has the same steps.
